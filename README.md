# 健康分诊（triage）

一个纯前端的健康自查工具：**点几下把「要不要去医院」问清楚**，另配 AI 问答与疾病百科。
不装 App、不注册也能用；登录后对话可云端保存，额度从 5 次/天提到 20 次/天。

- 线上地址：https://triage.app.workbuddy.host/?sharecode=AIV3ZFRC47
- 技术栈：原生 HTML/CSS/JS（无框架、无构建）+ WorkBuddy Cloud（Postgres / Auth / LLM）
- 代码规模：核心代码约 4 600 行，11 个 JS 模块 + 40 个数据文件（17 棵树 / 23 个科室）

---

## 1. 它解决什么问题

网上查症状的典型失败方式是：搜到一个吓人的病名，然后越查越焦虑。这个工具反过来做：

1. **先用决策树排除危险信号**（骨折、急症），再谈处理方式；
2. **结论固定分四级**，不说「可能有问题」这种没用的废话；
3. **每棵树的第一问永远是最危险的那个分叉**，而不是最常见的那个。

四级结果：

| 等级 | 含义 | 颜色 |
|---|---|---|
| L0 | 居家观察 | 绿 `#10B981` |
| L1 | 居家处理 | 黄 `#EAB308` |
| L2 | 尽快就诊 | 橙 `#F97316` |
| L3 | 立即就医 | 红 `#EF4444` |

## 4. 本地运行

任何静态服务器都可以，不需要构建：

```bash
cd html8
python -m http.server 8799
# 打开 http://127.0.0.1:8799/index.html
```

> 直接双击 `index.html` 也能看大部分页面，但 AI 与账号功能需要 `http(s)` 环境，否则跨域和存储会受限。

云服务配置在 `assets/cloud-config.js`：

```js
window.CLOUD_CONFIG = {
  endpoint: 'https://triage.app.workbuddy.host',
  publishableKey: 'wbpk_...'
};
```

## 5. 数据层

三张表，全部开启 RLS。除 `conversations` 外，业务表**不给 anon/authenticated 任何 GRANT**，只能通过 `SECURITY DEFINER` 函数读写。

### 5.1 `drugs`（药物库，46 条：OTC 32 + 处方 14）

| 列 | 类型 | 说明 |
|---|---|---|
| `brand` | text | 品牌名（用户看得懂的名字，如「感冒灵颗粒」） |
| `generic` | text | 成分说明 |
| `tags` | text[] | **口语症状词**（发烧/嗓子疼/拉肚子/崴脚/扑热息痛），靠它匹配 |
| `dose` | text | 成人常规剂量（**保留在库，但不再对外输出**） |
| `dose_child` | text | 儿童剂量（同上，仅存档） |
| `pregnancy` | text | 孕期 / 哺乳期说明 |
| `child_ok` | bool | 儿童是否可用 |
| `caution` | text | 关键提醒（如「已含对乙酰氨基酚，不要再叠加布洛芬」） |
| `warn` | text[] | 必须提醒项（如头孢的「停药 7 天内不能喝酒」） |
| `otc` | bool | 是否非处方（处方药不会出现在「你吃过什么药」选项里） |

检索函数 `drug_lookup(p_text)`：只检索 `otc = true` 的条目（**处方药不对外**），对 `tags` 做 ILIKE 匹配，按命中数排序，最多返回 8 条，且不返回剂量字段。

### 5.2 `ai_quota_usage`（额度计数）

复合主键 `(scope, subject, day)`；`scope` 为 `guest` / `user`，`subject` 为设备指纹或用户 UUID，`day` 为 `CURRENT_DATE`。跨天自动归零，**不需要定时任务**。

### 5.3 `conversations`（对话历史）

`id / owner_id / title / messages(jsonb) / created_at / updated_at`，依赖 RLS 做本人隔离。

### 5.4 函数

| 函数 | 作用 |
|---|---|
| `ai_quota(p_action, p_fp)` | `check` / `consume` / `refund`，返回 `{scope, limit, used, remaining, allowed}` |
| `drug_lookup(p_text)` | 按用户原话检索药物，返回 JSON 数组 |

## 6. AI 设计

### 6.1 提示词分四层

固定 system 提示词只写**规则**，事实全部外置：

```
基础规则（格式 / 分块 / 不做诊断 / 危险信号）
  ＋ 患者画像（每次请求注入）
  ＋ 药物资料（按需注入，检索命中才拼）
  ＋ 最近 8 条对话
```

### 6.2 结构化输出协议

模型被要求在正文前先给一句结论，再用【】分块，每块 2–4 条：

```
病毒性感冒可能性大，先对症处理，不用抗生素。
【可能是什么】
- 普通病毒性感冒 …
【现在能做什么】
- 多喝温水 …
【什么情况要去医院】
- 高热超过 3 天 …
```

前端 `renderRich()` 解析成卡片，**按标题关键词自动配色**：命中「就医/医院/急诊」→ 红，命中「药」→ 琥珀，「现在/能做」→ 青，「可能/是什么」→ 紫，兜底灰。模型换说法也能正确着色。

### 6.3 信息不足先追问（不硬下结论）

缺部位 / 时长 / 伴随症状时，模型只输出一个确认块：

```
【需要确认】
- 疼的位置主要在哪儿？ => 上腹部 | 肚脐周围 | 右下腹
- 什么感觉？ => 隐隐作痛 | 绞痛 | 烧灼感
- 持续多久了？ => 几小时内 | 一两天 | 超过三天
```

前端把它变成底部弹层：**一次最多 3 个问题、最多两轮**，每题可选可手写，全部答完才能提交。
用户选完后**不新增用户气泡**，答案并入原确认卡，AI 接着在同一条对话里给判定。

### 6.4 主动问用药史

症状属于可自行用药类型（发热/疼痛/腹泻/过敏/咳嗽/咽痛/胃痛/扭伤）时，给结论前必须问一句「这次已经吃过药了吗？」，
选项由 `drug_lookup` 出的品牌名填充，第一个固定「没有」。

拿到用药后强制三件事：

1. 第一句就点明「已经吃过 X，别再叠加 Y」；
2. 单独给一个琥珀色【用药提醒】块（间隔时间 / 不能叠加的成分 / 超量伤什么器官）；
3. 涉及抗菌药、处方药、超量 → 建议停药就医。

硬规则：用户提到**头孢**时，第一句就要说「7 天内不能喝酒」，不等问完流程。

### 6.5 不给剂量、不下诊断

出于合规（免费公开使用），AI 被明确禁止输出任何具体用量：

- 不许写 mg / g / ml / 片数 / 粒数 / 袋数 / 喷几下 / 每天几次
- 统一说「按说明书剂量服用」或「按药师指导服用」
- 不写「你得了 X」，只写「常见于」「可能是」，把握不足就建议就医

结果页与分享长图同样删掉了写死的剂量，只保留「能不能用、别和什么混着用」。

### 6.6 患者画像

进入 AI 页先确认「性别 + 年龄段（+ 女性育龄的特殊状态）」，之后每轮自动注入：

```
【患者信息｜每次回答都必须按这个人给剂量和建议】
性别：男
年龄：4–6 岁
→ 这是儿童：只给药物资料里「儿童」那一条；资料写不建议就建议就医，
  禁止把成人剂量减半、禁止让儿童掰成人药片。
```

对话开始后这三个下拉框锁定，要改必须开新对话（避免同一段上下文里混用两个患者）。

### 6.7 设置：账号 / 回复块 / 字号 / 背景

设置入口在个人信息里：登录后点头像 →「设置」；未登录时用页头右侧的齿轮。
抽屉最上面是**账号区**（仅登录后出现）：显示当前邮箱或打码手机号，右侧「修改密码」展开三行表单——
当前密码 / 新密码 / 确认新密码。校验在提交前完成（非空、≥6 位、两次一致、新旧不同），
提交走 `cloud.auth.resetPasswordForOld({ oldPassword, newPassword })`：SDK 先 `POST /v1/user/sudo`
验旧密码拿 `sudo_token`，再 `PATCH /v1/user/password` 写入新密码。改完不退出登录，下次登录用新密码。
关闭抽屉会清空输入框；`unauthenticated` 与网络错误分开提示。
**没设过密码的账号改不了**（sudo 需要旧密码，服务端也无补设接口），错误提示里写明了这一点。

下面是三组外观设置——回复块、字体大小、背景颜色。**回复块**逐行开关决定回复里固定包含哪些块。默认：

| 块 | 默认 | 可关 |
|---|---|---|
| 初步结论、需要确认（追问） | 开 | 否（骨架与追问流程依赖） |
| 病因分析、解决方案、就医指征、用药指导、就诊提问清单 | 开 | 是 |
| 病程与预后、活动与工作建议 | 关 | 是 |

**就诊提问清单**是为线下就诊准备的：给 3–5 个能直接照着问医生的问题（要做什么检查、判断依据、
治疗方案怎么选、多久复查），帮医生更快抓到重点。

开关语义是「**开 = 不许省略，关 = 不许出现**」，不是无条件硬塞：模型仍判断相关性，只是不许在自己的判断范围内省略。

设置存 `localStorage['triage.blocks.v1']`（块）与 `triage.ui.v1`（字号 `s/m/l`、背景 `mint/white/gray/cream`），
没有 key 就等于默认；抽屉底部「全部恢复默认」把两者一起清掉。
字号通过 `body[data-fs]` 改写 `--fs-bub` / `--fs-blk` 两个 CSS 变量，背景通过 `body[data-bg]` 命中选择器。

每轮把块的选择拼成一段注入 system：

```
【输出块设置｜用户自选，优先级低于安全底线】
必须包含（不许省略，按此顺序）：可能是什么、现在能做什么、什么情况要去医院、用药提醒
禁止输出：多久能好、要不要请假能不能运动
此设置不覆盖安全底线：出现危险信号、或涉及药物禁忌时，仍须给出一句话提醒。
```

**三条不被开关覆盖的底线**：头孢等禁忌、危险信号首句提醒、不给剂量不下诊断——这些属于安全与合规规则，不是「块」。

## 7. 额度系统

| 身份 | 额度 | 计数键 | 重置 |
|---|---|---|---|
| 游客 | 5 次/天 | 设备指纹 + 本地设备 ID（双键归并） | 每天 0 点 |
| 新注册账号 | 首日 5 次 | 用户 UUID | 注册满 24 小时转 20 次/天 |
| 登录（满 24 小时） | 20 次/天 | 用户 UUID | 每天 0 点 |

**为什么要卡新号首日**：手机号验证码注册成本极低（虚拟号一两毛一条），不卡就等于每换一个号白拿 20 次。
`user_first_seen(uid, first_at)` 记录首次使用时间，`ai_quota` 里按 `now() - first_at < 24h` 决定给 5 还是 20。

### 登录方式

手机号和邮箱两条路并存，手机号下再分密码登录与验证码登录：

| 方式 | 流程 | 说明 |
|---|---|---|
| 手机号 + 密码 | 输号 + 密码 → 登录 | 日常登录走这条 |
| 手机号 + 验证码 | 输号 → 取码 → 验证 → 登录/注册 | 新号在这一步**必须设密码**，因为密码只能在注册时写入 |
| 邮箱 | 密码登录，或验证码注册 | 原有方式，保留给不想给手机号的人 |
| 邮箱忘记密码 | 邮箱 → 收码 → 设新密码并自动登录 | `resetPasswordForEmail(email)` → 验证码 → `updateUser({nonce,password})` |
| 手机号忘记密码 | **做不到** | SDK 未开放手机号找回；退回「验证码登录」，不需要密码 |

**为什么注册必须设密码**：SDK 只有 `signUp({phone, password, verificationToken})` 能写密码，
没有"给已有账号补设密码"的接口（`resetPasswordForEmail` 只支持邮箱；`resetPasswordForOld` 要求先知道旧密码）。
所以手机号注册那一刻没设密码，这个号就永远只能验证码登录。前端在验证码路径里做了拦截：
`isExistingUser === false` 且密码不足 6 位时直接报错，不放行。

**改密码**走 `resetPasswordForOld`（旧密码 → sudo 票据 → PATCH 新密码），入口在设置抽屉的账号区，
邮箱与手机号账号都能用，前提是这个账号设过密码；从没设过密码的账号改不了，只能换号重新注册。

**忘了密码**在登录页邮箱面板的「忘记密码？」里：`resetPasswordForEmail(email)` 发 `PASSWORD_RESET` 验证码，
用户填码 + 新密码后由 SDK 的 `updateUser({nonce,password})` 完成验证、`PATCH /v1/reset` 改密并自动登录。
这条路径**不要求旧密码**，所以从没设过密码的邮箱账号也能借此设一个新密码。手机号没有对应能力，见上表。

**身份缓存只留一个**：`triage.email` 与 `triage.phone` 互斥——邮箱登录写 email 并删 phone，手机号登录写 phone 并删 email，
退出两者都删。页头与账号菜单先按 `triage.phone` 兜底（打码手机号，没有就「已登录」），`resolveEmail()`
真查到邮箱再覆盖；**解析不到必须清空，不能留上一次的值**，否则同一页面里换账号后菜单会挂着上一个账号的邮箱。

短信由云服务商发出（`cloud.auth.sendOtp({ phone })`），**不需要接第三方短信平台**，也不需要企业实名与签名报备。
本地还有一道限流：同一号码 60 秒冷却、每天最多 5 条（`triage.otp.rl.v1`），刷新也拦得住。

### 计次口径：按「用户发送」而不是「模型调用」

`Quota.consume()` 只在**用户主动发出一条消息**时调用一次。AI 追问后用户在弹窗里选答案，
属于同一轮的继续生成，走 `send({ silent: true })`，**不再扣次数**（多轮追问也只在第一次计入）。

所以「提问 → 弹窗 → 选择 → 回答」这整套下来是 **1 次**，尽管底层调用了两次模型。
实现上 silent 分支连 `consume()` 都不进，用 `gate.degraded = true` 占位，
这样收尾的 `refund()` 也会自动跳过（没扣过就不该退）。

### 为什么不按 IP

这个平台的边缘节点会**覆盖真实 IP**：实测同一台机器多次请求分别落在 `82.157.138.133` / `82.157.30.58` / `81.70.36.92`，
而本机真实出口是另一个地址。按 IP 计数会导致「同一个人 5 次永远用不完，不相干的两个人被算成一个人」。
所以**从第一版起就没有启用过 IP 计数**，不是后来关掉的。

### 设备指纹 + 本地 ID（双键）

客户端把 UA、平台、语言、CPU 核数、内存、触屏点数、色彩深度、时区、canvas 渲染结果、WebGL renderer
拼起来做 FNV-1a 双种子哈希，得到 16 位字符串；同时用 `localStorage` 存一个随机本地 ID（`triage.did`）。

两个键一起发给 `ai_quota(p_action, p_fp, p_lid)`，服务端在**今天**的游客记录里按
`subject IN (fp, lid) OR lid IN (fp, lid)` 查找，命中就沿用那条，并把别名行归并掉。
任一键还在，计数就不会重置。

**为什么需要双键**：指纹里的 `screen × dpr` 会随浏览器缩放变化（实测 Ctrl+加减号后指纹从
`d1e654…` 变成 `d19bcb…`，等于白拿 5 次），已改为只取 `colorDepth` 等稳定项；
即使如此，换 UA、换设备仍会改变指纹，这类情况由本地 ID 兜住；反过来清缓存会丢本地 ID，由指纹兜住。

**边界**：两个键同时变化（换设备 + 清缓存）就是新访客；懂技术的人可以绕过页面直接调 API。
前端限制管不住，也不假装能管住。真正抗刷要靠服务端限流。

### 身份判定（踩过的坑）

`ai_quota` 早期用 `is_anonymous` 判断游客/正式用户。但这个 claim **只有游客 token 才有**，
正式用户 token 里没有这个键 → `coalesce(..., true)` 取到默认值 → 永远判成游客，表现为「登录后底部还写游客」。

现在以 `auth.uid()` 为主判据：uid 是真实 UUID 就算正式用户，uid 是字符串 `anon` 才算游客，`is_anonymous` 只作否决项。

### 微信里怎么存下来

这是踩坑最深的一处，结论：

| 环境 | `<a download>` | 长按 `blob:` 图片 | 结论 |
|---|---|---|---|
| 微信 / QQ 内置浏览器 | 无效 | 不出「保存图片」菜单 | 两条路都断 |
| 桌面浏览器 | 可用 | — | 用下载按钮 |

最终方案：

1. `FileReader.readAsDataURL()` 把 blob 转成 `data:image/png;base64,...` 再交给 `<img>`（微信长按只认 `http(s)` 和 `data:`）；
2. 微信 UA 下**直接进全屏看图**，隐藏所有按钮，只留右上角关闭 + 底部提示「长按图片 → 选保存图片」；
3. 桌面只保留「保存图片」，不再调用系统分享（Windows 的分享面板经常没有可用目标，必然失败）。

## 11. 已知限制

1. **药物剂量是科普级，不是药典级**。按公开说明书整理，上线给真实患者使用前**必须由药师逐条审核**。
2. **患者年龄是区间不是精确值**。儿童剂量依赖体重，所以让模型追问体重，而不是按年龄硬算。
3. **额度可被换设备 / 改 UA 绕过**，也可被直接调 API 绕过。
4. **AI 只答医学问题**，靠提示词约束，没有内容审核层。
5. **微信长按保存依赖 data URL**，部分安卓 X5 内核对超长 base64 图片可能仍有限制，兜底是截屏。
6. **没设过密码的账号无法补设，也无法改密**。`resetPasswordForOld` 要旧密码，`resetPasswordForEmail` 只认邮箱，
   手机号账号一旦用验证码注册时没填密码，只能继续验证码登录。

## 12. 常见改动指引

**加一棵决策树**：在 `assets/trees/` 新建文件，`TREES.push({...})`，`type:'q'` 是问题节点、`type:'r'` 是结果节点（必须带 `level` 和 `verdict`），最后在 `index.html` 里加 `<script>`。

**改药**：直接 `UPDATE drugs SET dose=... WHERE brand=...`，不用改代码、不用重新部署。

**改 AI 行为**：`assets/ai.js` 顶部的 `SYSTEM` 数组。原则是**只写规则不写事实**——剂量、禁忌、药名都从数据库取。

**加额度档位**：改 `ai_quota()` 里的 `v_limit`，同时改 `quota.js` 的 `label()` 文案。
